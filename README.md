# 芝麻開門（Door Sesame）Android App

目前修改版：**v13 個人化 Log 與歷史規律統計**（以 v12 專案為基礎）。

手機端程式：使用 Android 地理圍欄省電監控住家附近，離開地理圍欄範圍（預設 55 公尺，可在設定頁調整）後布防；再次進入範圍時才短暫啟動定位確認。靠近門口後依原本設定送出 eWeLink Intent，或把位置回報給 VM。

**注意：此版本原始碼尚未在本環境編譯或實機測試。** 請先用測試環境驗證地理圍欄事件、背景權限與實際開門流程，再日常使用。

## 編譯步驟（Android Studio 免費）

1. 安裝 Android Studio，新建專案：選 **Empty Views Activity**（若沒有就選 No Activity），
   Language 選 **Kotlin**，Package name 填 `com.example.dooropener`，Minimum SDK 選 API 26。
2. 把本資料夾的檔案複製進專案（覆蓋同名檔案）：
   - `app/src/main/AndroidManifest.xml`
   - `app/src/main/java/com/example/dooropener/MainActivity.kt`
   - `app/src/main/java/com/example/dooropener/DoorService.kt`
   - `app/src/main/java/com/example/dooropener/GeofenceManager.kt`
   - `app/src/main/java/com/example/dooropener/GeofenceReceiver.kt`
   - `app/src/main/java/com/example/dooropener/GeofenceBootReceiver.kt`
   如果專案原本有自動產生的 layout 檔或 `activity_main.xml`，可以刪掉，這個 App 用程式碼建畫面。
3. 打開 `app/build.gradle(.kts)`，在 `dependencies { }` 裡加入：
   ```
   implementation("com.google.android.gms:play-services-location:21.3.0")
   implementation("androidx.core:core-ktx:1.13.1")
   ```
   如果專案是 Groovy 格式的 `build.gradle`，寫法是
   `implementation 'com.google.android.gms:play-services-location:21.3.0'`。
4. 按 Sync，接上手機（開啟 USB 偵錯）或用 Build > Build APK，安裝到手機。

## 使用

1. 開啟 App，填入伺服器網址（`https://你的網域/arrive`）、密碼、門口經緯度，按「儲存並啟動」。
2. 依序允許：精確位置、通知及「一律允許」背景位置；再按「儲存並啟動」註冊地理圍欄（預設半徑 55 公尺，可在「進階參數」調整）。
3. 平常地理圍欄註冊後會停止連續定位；離開住家範圍後布防，回到範圍才開始短時間定位確認，最長時間預設 5 分鐘（可調）。
4. 到手機設定把本 App 的電池用量設成「不受限制」。小米、OPPO、三星等品牌另有「自啟動」與「背景限制」要開。
5. 按「停止」會移除地理圍欄；再次啟動需要重新註冊。

## 排錯：進入圍欄沒反應時怎麼看

設定頁最下方會即時顯示「圍欄是否啟用、是否已布防、已儲存座標、各項權限、事件紀錄」，進出圍欄時也會跳出通知（獨立的高重要性頻道）。

- 看到「偵測到進入住家範圍，但尚未布防」：代表沒有先離開圍欄半徑（預設 55 公尺）外。請在圍欄外按「儲存並啟動」，等紀錄出現「已布防」，再走進來。
- 完全沒有任何紀錄：圍欄事件根本沒到。檢查已儲存座標是否為新座標、背景位置是否「一律允許」、電池是否「不受限制」、手機定位與 Wi-Fi 掃描是否開啟。
- 「無法啟動前景定位服務」：背景位置不是「一律允許」。
- 「位置確認逾時」：進入圍欄但逾時前沒有「連續 N 筆」同時符合抵達距離與誤差上限；到設定頁「進階參數」放寬「最大允許定位誤差」、「抵達距離」或減少「連續筆數」。
- 更新座標：App 內的預設座標只在手機沒存過座標時才會顯示，已存過的要在設定頁手動改，再按「儲存並啟動」。
- 覆蓋安裝新版或重開機後，會自動重新註冊圍欄；若仍無反應，請手動再按一次「儲存並啟動」。

## 已知限制

- 地理圍欄在手機重開機後會嘗試重新註冊；若系統限制背景啟動、權限變更或小米省電管理攔截，仍需手動打開 App 重新按「儲存並啟動」。
- 地理圍欄事件可能延遲，不能保證一到門口立即觸發；實際可靠度需在你的手機與常走路線測試。
- 密碼存在 App 私有的 SharedPreferences，沒有額外加密。
- 圍欄半徑、抵達距離、定位誤差、連續筆數、定位頻率、逾時都改成在設定頁「進階參數」調整，不用重新編譯（預設值定義在 `DoorConfig.kt`）。
- 55 公尺的圍欄小於 Google 建議的最小半徑（約 100 公尺），Play 服務的圍欄偵測在小半徑時可能延遲甚至漏觸發；若發現常常沒反應，先把圍欄半徑調大（例如 100～150），再靠「抵達距離」與「連續筆數」把關開門。

## 不裝 Android Studio：用 GitHub Actions 編譯

專案已含 settings.gradle.kts、build.gradle.kts、app/build.gradle.kts 與 `.github/workflows/build.yml`。

1. 在 GitHub 建一個新的 repository（建議 Private），把本資料夾的內容上傳（保留 `.github` 資料夾）。
2. 到 repository 的 Actions 頁籤，選 **Build APK**，按 **Run workflow**（推送到 main 也會自動執行）。
3. 跑完後點進該次執行，在 Artifacts 下載 `door-apk`，解壓得到 `door.apk`，傳到手機安裝
   （手機要允許「安裝未知來源的應用程式」）。
4. 若建置失敗，打開失敗步驟的紀錄，把錯誤訊息貼給我。

注意：repository 裡不要放密碼。伺服器網址、密碼、門口座標都是在手機 App 裡輸入，不在程式碼裡。

## 本機模式：直接啟動 eWeLink 捷徑（不經伺服器，不用等審核）

原理：App 在距離「抵達距離」內（預設 15 公尺）、定位誤差在上限內（預設 15 公尺），且連續符合指定筆數（預設 2 筆）時，直接發出 eWeLink 手動情境捷徑的 Intent。
**這個模式未經驗證**，能不能成功取決於 eWeLink 的捷徑指令格式與你的手機系統。

### 查出捷徑的 Intent（需要一台電腦，免費）
1. 先在 eWeLink 建立「手動情境」（動作：開那一路門，該路設成點動），並加到手機主畫面。
2. 手機開啟「開發人員選項」>「USB 偵錯」，接電腦，裝好 adb（Android platform-tools）。
3. 找出 eWeLink 的套件名稱：
   `adb shell pm list packages | grep -i -E "coolkit|ewelink"`
4. 列出捷徑資料，在該套件底下找 `intents=` 那一行（action、data、component）：
   `adb shell dumpsys shortcut`
5. 把找到的內容改寫成 Intent URI，格式例如：
   `intent:#Intent;action=android.intent.action.VIEW;component=套件名/類別名;end`
   （若有 data，寫成 `intent:資料#Intent;action=...;end`）
6. 先用 adb 測試能不能讓門動作：
   `adb shell am start "intent:#Intent;...;end"`
   （若 `am start` 不吃 intent: 格式，改用 `-a`、`-n`、`-d` 參數拆開寫）
7. 確定有效後，把 URI 貼進 App 的最後一個欄位。

### 已知限制
- 需要「顯示在其他應用程式上層」權限，背景服務才能啟動畫面（Android 10 以後的限制）。
- 手機鎖屏時能不能執行，取決於該捷徑是否真的會背景執行；若需要解鎖畫面才能動作，這個模式在口袋裡就無效。
- 本機模式沒有伺服器的冷卻時間與時段限制，只有 App 內建的 5 分鐘暫停。
- 手機被別人拿到時，捷徑本身也能開門，安全性比伺服器模式低。

## 語音開門：「Hey Google，開啟芝麻開門」

- App 名稱為 **芝麻開門**，圖示採用金色門扉設計，不使用 Android 機器人圖示。
- 點主圖示會執行開門入口；主圖示長按可選「設定」進入設定頁。
- 優先測試「Hey Google，開啟芝麻開門」。已加入名稱為「開門」的 App 捷徑，可嘗試用較短指令呼叫；Google 助理是否能直接識別短捷徑，依手機上的助理版本與設定而異，不能保證。
- 開門入口本身使用透明、無標題列 Activity，成功時不顯示芝麻開門畫面或成功 Toast；目標 eWeLink 畫面仍可能依 Intent 顯示。
- 成功開門後 10 秒內再次觸發會被忽略。
- 若助理把「大門」當成智慧家庭裝置而不是 App，請到 Google Home 把同名裝置改名或取消連結。

## 抵達時的開門方式（v2）

抵達確認後，與點圖示／語音使用同一個入口 `OpenDoorActivity`：
1. 先掛上「全螢幕通知」當備援，再直接啟動 `OpenDoorActivity`。
2. 若系統擋下背景啟動，全螢幕通知會拉起同一個入口；螢幕亮著時可能只顯示成浮動通知，點一下即可。
3. `OpenDoorActivity` 啟動後會取消該通知，並有 10 秒冷卻避免重複開門。
4. Android 14 以上要到設定頁按「開啟全螢幕通知權限」手動允許（診斷區會顯示 ✓/✗）。
5. 若鎖屏時 eWeLink 本身仍需要解鎖才會執行情境，這個限制 App 無法繞過。

## v9：以 v5 為基礎加上一鍵設定精靈
設定頁最上方「一鍵設定所有權限」會依序跳到：位置／通知 → 背景位置 → 顯示在上層 → 電池不受限 → 全螢幕通知 → 廠牌額外設定（小米：鎖定螢幕上顯示、後台彈出、自啟動）。已完成的自動略過，從設定頁返回會自動帶到下一項。
Android 不允許 App 替使用者直接開啟權限，每一項仍要在系統畫面點一下；廠牌額外設定無法偵測是否已開。
小米另外請手動把「Google Play 服務」的省電策略設為無限制並允許自啟動（地理圍欄由它執行）。

## v10：兩種停用
- 「停用地理圍欄服務」：移除圍欄、停止定位服務，圖示／語音／捷徑開門照常可用。
- 「全部停用」：再加上讓圖示／語音／捷徑都不開門（點圖示只會開啟設定頁），並取消所有通知。
- 「解除全部停用」恢復圖示／語音開門；按「儲存並啟動」則會連同地理圍欄一起重新啟用。

## v11：可自訂圍欄與定位參數
設定頁新增可收合的「進階參數」，改完按「儲存並啟動」即套用（只有圍欄半徑需要重新註冊，按儲存時會自動做）。欄位留空＝預設值；輸入有誤會顯示哪一欄、整組不存。

| 參數 | 預設 | 說明 |
|---|---|---|
| 地理圍欄半徑 | 55 公尺 | 離開此範圍後布防，回到範圍內才開始精確定位 |
| 抵達距離 | 15 公尺 | 定位點離門口多近才算符合；不可大於圍欄半徑 |
| 最大允許定位誤差 | 15 公尺 | 誤差超過就不採用該筆定位 |
| 連續筆數 | 2 筆 | 連續符合（距離＋誤差）幾筆才開門；中間有一筆不符就重算；1 ＝單筆就開 |
| 靠近時定位間隔 | 2.5 秒 | 高頻範圍內，高精度定位的更新間隔 |
| 距離較遠時定位間隔 | 15 秒 | 高頻範圍外，省電模式的更新間隔 |
| 高頻定位範圍 | 80 公尺 | 距門口多近開始用高精度＋短間隔 |
| 定位確認逾時 | 5 分鐘 | 進入圍欄後最久持續定位多久 |

- 進入圍欄後一開始就用高精度（靠近間隔）定位，第一筆定位若顯示距離仍超過高頻範圍，才降回省電模式。
- 診斷區新增「目前參數」一行，確認中的狀態會顯示「連續符合 n/N 筆」。
- 圖示改為緊裁切版：人物與門放大、岩壁壓暗，並改用 Adaptive Icon（前景在 `mipmap-*/ic_launcher_foreground.png`）。

## v12：雲端開門（eWeLink Cloud API）
eWeLink 開發者應用通過審核後，可以不再依賴手機上的 eWeLink 捷徑（Intent），改由自己的伺服器呼叫雲端 API 開門。
伺服器程式在 `server/`，部署步驟見 `server/README.md`。

- **Intent URI 改成選填**：留空＝走伺服器。有填 Intent 就維持原本的本機捷徑行為。
- 要走伺服器：填好「伺服器網址」（`https://你的網域/arrive`）與「密碼」，Intent 留空，再按「儲存並啟動」。網址必須是 https。
- 伺服器模式下，圖示／語音／「手動開門」會呼叫伺服器的 `/open`；抵達時由手機確認位置後呼叫 `/arrive`。不需要解鎖手機，也不需要「顯示在上層」或全螢幕通知。
- 「模擬抵達」在伺服器模式下，會用門口座標走一次完整的 `/arrive`（伺服器照樣檢查、記錄、開門），站在門邊測最準。
- 抵達回報多帶了診斷欄位（定位時間、是否模擬定位、連續筆數、收到幾筆定位、進圍欄後多久抵達、目前參數），伺服器用它們做防誤開門與 `/stats` 分析。
- 設定頁「進階參數」新增「從伺服器同步參數」：只在按下時連線一次，把伺服器 `/config` 的數值填進欄位，確認後按「儲存並啟動」才套用。定位頻率仍由手機執行，不會一直向伺服器查詢。


## v13：三支手機分流 Log 與個人化回家時段統計

- 設定頁新增「個人代號」，三支手機請分別填 `A`、`B`、`C`；App 另外產生固定的安裝識別碼 `deviceId`，每趟回家使用 `sessionId` 串接事件。
- App 將事件和定位確認階段的抽樣座標暫存於 App 私有目錄，HTTPS 可用時批次補傳；失敗會保留佇列，並限制自動重試頻率，避免網路故障時反覆耗電。
- Log 包括圍欄進出、服務啟停、設定版本與定位參數、定位距離／誤差／速度／方向、連續符合筆數、伺服器回應及開門結果。
- VM 新增 `POST /telemetry/batch`、`GET /telemetry`、`GET /analytics`；資料會寫入 `server/data/telemetry.jsonl`，抵達與開門決策仍寫入 `server/data/arrivals.jsonl`。兩種紀錄分開儲存並以事件 ID 去重。
- `/analytics` 提供每個 profile 的星期別典型抵達時段、今天對應的歷史時間窗、個別定位品質，以及跨手機的定位誤差共用基準。報表需要帶入既有 `SHARED_SECRET`，例如 `/analytics?key=你的密碼&format=text`；按 `profileId=A` 可只看單一個人。
- **本版不會全天追蹤 GPS**：位置樣本主要在進入住家圍欄、短暫定位確認時收集。此版可以建立歷史回家時段和門口定位品質統計，但還不能根據整段通勤路線預測即時剩餘 ETA。若後續要做途中 ETA，需另行設計可選擇、低頻、限時的通勤追蹤與 Android 活動辨識。
- 歷史統計只做參考，不會直接觸發開門或自動放寬安全條件。請先累積數週資料，再依報表人工確認是否調整參數。
- **隱私提醒**：VM 會保存定位確認階段的精確座標。伺服器 log 檔只允許擁有者讀取；仍應限制 VM 管理權限及備份存取。`profileId` 只用於統計分組，若三支手機共用一個密碼，不能視為真正的個別身分認證。
